# Генератор российских (и не только) тестовых данных

Ускоряйте разработку с мгновенной генерацией приближённых к реалистичным тестовых данных прямо в редакторе кода.

## ⚠️ Важно

Любые совпадения с реальными конфиденциальными данными (ИНН, номера счетов, номера карт, СНИЛС, номера телефонов, наименования организаций,
ОГРН, ОКТМО и другие) являются случайными и не предназначены для использования в реальных системах.

Все данные генерируются **локально внутри плагина**, без обращений к внешним сервисам.

## ✨ Основные возможности

- 🚀 **Быстрая генерация** данных прямо в редакторе
- ⌨️ **Горячие клавиши** (по умолчанию Ctrl+Alt+E, можно переназначить)
- 🎛️ **Гибкие настройки генераторов** (порядок, включение/отключение, переименование)
- 💬 **Символ обрамления** при вставке в редактор (двойные кавычки, одинарные, без обрамления)
- 🔔 **Настраиваемые уведомления** о срабатывании генераторов
- 👀 **Предпросмотр результата** перед вставкой
- 📋 **Интеграция с Alt+Ins** — доступен в стандартном диалоге генерации кода IntelliJ
- 🔄 **Обновления без сброса настроек** — порядок, активность и пользовательские имена генераторов сохраняются автоматически

# 🤖 MCP-сервер

Помимо плагина для IntelliJ IDEA, Ru BizGen доступен как **MCP-сервер** (Model Context Protocol).
Это позволяет подключать генерацию тестовых данных к любым MCP-совместимым AI-клиентам
(Claude Desktop, Cursor, Cline, Windsurf и др.) и генерировать данные прямо в чате или через AI-агента.

Все данные генерируются **локально**, без обращений к внешним сервисам — так же, как в плагине.

## ✨ Возможности

- 🧩 **5 категорийных MCP-инструментов** — `ru-bizgen_generator_<category>` с параметром `type` (enum) для выбора генератора и опциональным `count`
  для пакетной генерации (до 1000 значений за вызов)
- 🔒 **Полностью локальная генерация** — нет сетевых вызовов, данные не покидают ваш компьютер
- ⚡ **Микросекундная производительность** — те же алгоритмы, что и в плагине
- 🌐 **Streamable HTTP транспорт** — современный MCP-протокол поверх HTTP
- 🐳 **Docker-ready** — готовый `Dockerfile` и `docker-compose.yml`
- 📋 **Стабильные `type`-ключи** — значения enum вычисляются из UUID-идентификаторов генераторов, а не из имён классов, и не меняются при
  рефакторинге

## 🛠 Технологический стек

| Компонент      | Версия          |
|:---------------|:----------------|
| MCP Kotlin SDK | 0.15.0          |
| Ktor / Netty   | 3.5.1           |
| JDK            | 21              |
| Транспорт      | Streamable HTTP |

## ▶️ Быстрый старт

MCP-сервер можно запустить тремя способами.

### Способ 1. Gradle (из исходников)

```bash
# Сборка дистрибутива
./gradlew :ru-bizgen-mcp:installDist

# Запуск (по умолчанию 127.0.0.1:8081)
./ru-bizgen-mcp/build/install/ru-bizgen-mcp/bin/ru-bizgen-mcp

# С явным указанием host/port
./ru-bizgen-mcp/build/install/ru-bizgen-mcp/bin/ru-bizgen-mcp --host=0.0.0.0 --port=9090
```

### Способ 2. Docker

```bash
docker build -f ru-bizgen-mcp/Dockerfile -t ru-bizgen-mcp .
docker run -p 8081:8081 ru-bizgen-mcp
```

### Способ 3. Docker Compose

```bash
docker compose -f ru-bizgen-mcp/docker-compose.yml up -d
```

После запуска сервер доступен по адресу `http://127.0.0.1:8081`.

## ⚙️ Конфигурация

Параметры передаются как аргументы командной строки:

| Параметр  | По умолчанию | Описание                                        |
|:----------|:-------------|:------------------------------------------------|
| `--host=` | `127.0.0.1`  | Адрес для привязки (`0.0.0.0` — все интерфейсы) |
| `--port=` | `8081`       | Порт MCP-сервера                                |

### Healthcheck

Эндпоинт `GET /health` возвращает `{"status":"UP"}` — удобно для Docker healthcheck и мониторинга:

```bash
curl http://127.0.0.1:8081/health
```

## 🔌 Подключение MCP-клиента

MCP-сервер использует **Streamable HTTP** транспорт. Эндпоинт MCP — `http://127.0.0.1:8081/mcp`.

### Cursor

`Settings → Cursor Settings → MCP → Add MCP Server`:

```json
{
  "mcpServers": {
    "ru-bizgen": {
      "url": "http://127.0.0.1:8081/mcp"
    }
  }
}
```

### Claude Desktop

Добавьте в `claude_desktop_config.json` (поддержка Streamable HTTP в актуальных версиях):

```json
{
  "mcpServers": {
    "ru-bizgen": {
      "type": "streamableHttp",
      "url": "http://127.0.0.1:8081/mcp"
    }
  }
}
```

> **💡 Универсально:** любой MCP-клиент с поддержкой Streamable HTTP подключается по URL `http://<host>:<port>/mcp`.

## 🧩 Доступные инструменты (5 категорийных)

Имя каждого инструмента имеет формат `ru-bizgen_generator_<category>`. Каждый инструмент принимает:
- **`type`** (обязательный, enum) — выбор генератора внутри категории
- **`count`** (опциональный, int, 1..1000, по умолчанию 1) — количество значений для пакетной генерации

### `ru-bizgen_generator_technical` — Технические

| `uuid` | UUID как строка |

# ⚡ Отчет производительности

В этом разделе представлены результаты тестирования скорости работы генераторов, выполненные с
использованием [JMH](https://github.com/openjdk/jmh)
(Java Microbenchmark Harness).

Все измерения проводятся в изолированных условиях для обеспечения точности и воспроизводимости результатов.

## 🛠 Тестовое окружение

| Компонент                  | Спецификация                                                   |
|:---------------------------|:---------------------------------------------------------------|
| **Виртуальная машина**     | OpenJDK 64-Bit Server VM (21.0.11+10-LTS)                      |
| **Версия JDK**             | 21.0.11                                                        |
| **Фреймворк бенчмаркинга** | JMH 1.36                                                       |
| **Цель тестирования**      | Измерение среднего времени выполнения одного вызова генератора |

## ⚙️ Конфигурация JMH

Значения ниже соответствуют аннотациям `BaseGeneratorBenchmark`
(`ru-bizgen-perf/src/jmh/kotlin/.../bench/BaseGeneratorBenchmark.kt`).

### 📈 Режим измерений

* **Основной режим:** `AverageTime` (среднее время на операцию)
* **Единица измерения:** микросекунды (µs) на операцию

### 🔥 Фаза разогрева (Warmup)

Позволяет JVM выполнить оптимизацию кода и стабилизировать производительность.

* **Количество итераций:** 3
* **Длительность итерации:** 1 s

### ⏱️ Фаза измерения (Measurement)

Непосредственный замер производительности.

* **Количество итераций:** 10
* **Длительность итерации:** 2 s

### 🖥 Конфигурация JVM

Каждый тест запускается в отдельном процессе для чистоты эксперимента.

* **Количество процессов (Fork):** 2
* **Параметры JVM:** `-Xms1g -Xmx1g -XX:+UseG1GC -XX:+AlwaysPreTouch`
